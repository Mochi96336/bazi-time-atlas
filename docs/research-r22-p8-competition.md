# R22 P8｜資訊表達競爭（不再以外觀換皮）

## 競爭原則

以 P7 目前的三層 180° 低寬半圓作為 B0 基準（不變）。只加入兩個分離的讀法，不設計第二套時間演算法：

| 版本 | 實驗 URL | 它要回答的問題 | 與 P7 的本質差異 |
|---|---|---|---|
| B0 既有 | `?r22=1` | 三個標記目前位於何處？ | 標記與文字描述，維持舊版 |
| A 差距弧段 | `?r22=1&r22-study=gap` | 每層沿最短方向還差多遠到 0？ | 在**同一條**現有半圓軌道上畫出「標記—共同零點」的有號偏差弧段；閉合時長度歸零 |
| B 閉合條件 | `?r22=1&r22-study=closure` | 三個條件中已完成幾項？ | 三條半圓零點旁有固定閉合槽，閉合亮起、未閉合空心；顯示 1/3、2/3、3/3（Δ=0 僅標「基準」） |

**這不是色彩 A/B**。A 將「距離大小」編進空間弧長；B 將「是否滿足條件」編進閉合槽與總數。A 的危險是把最短餘數誤讀成實際時間旋轉；B 的危險是比左側原本標記更像儀表板。

## 絕對不能變

- 兩方案皆使用原生 `#recurrence-wheel`、同一 `setDelta` 與原生 Play 按鈕，不增設第二組滑桿或年月曆。
- 讀法只能由 `recurrenceState` 的現有相位派生；不可聲稱日序標記跑過了所有已完成的 60 日圈數。
- R16 完全不變，P7 `?r22=1` 完全不變；實驗只由 `r22-study=gap/closure` 明確開啟。
- 任何資料不可用（例如 2/29 加一年）不得畫成已閉合。
- +0 三層共用基準不是重新相遇的成果。

## 預先固定的比較樣本

同一基準日 2026-09-13，完全相同的瀏覽器來源和畫面大小：

| Δ | 公曆 | 年序 | 日序 | 理應看到 |
|---|---:|---:|---:|---|
| 0 | 0 | 0 | 0 | 基準狀態，不能假裝完成重遇 |
| 400 | 0 | −20 | −3 | 只有公曆閉合、另外兩項仍有差距 |
| 1,200 | 0 | 0 | −9 | 年序與公曆閉合，但日序還差 9 日 |
| 1,980 | −20 | 0 | 0 | 局部年＋日重遇，仍缺公曆 |
| 8,000 | 0 | +20 | 0 | 公曆＋日序閉合，年序尚未閉合 |
| 24,000 | 0 | 0 | 0 | 三個離散條件同時滿足；不是精確八字週期 |

至少使用 320 / 390 / 1440px 的真實瀏覽器畫面，B0/A/B 同年份比對。

## 審查紀律（借鑑 Folded Lattice 的設計競爭）

- **作者自評不得等同獨立評價**。本輪只能報告實作意圖、優缺點與可核實的畫面；如果沒有實際第二位評審，就必須註明未獨立審查。
- **裁決歸使用者**。無論哪版 CI 全綠、截圖較亮，都不能自行合併。
- 判讀測試優先於漂亮：遮住右邊數字，能否先在半圓辨識 +1,200 的兩層閉合與日序尚未歸零？
- 第二指標：對照 +400 與 +8,000，能不能辨認不同年份「缺的是哪層」？
- 風險：A 是否變成會誤導的進度表；B 是否變成三個小燈號的儀表板；320px 是否過度擁擠。
- **若兩方案都無法超越 P7**，保留 P7，不因為已花開發時間而強迫選一版。

## 驗收節點

先讓數學與真實 Chrome 檢查通過，再看同組 PNG 的資訊可讀性。**任何方案只有在實際判讀效果提升後才有資格進下一版**，而不是通過 CSS 斷言就改為 R22 預設。
