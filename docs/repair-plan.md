# 修復計畫（2026-11 接手後）

狀態：**進行中的工作計畫**。本文件排定接手後的修復順序；語意契約仍以 `docs/current-status.md`、`docs/architecture-contracts.md` 為準，Research 視覺規範仍以 `docs/research-visual-constitution.md` 為準。本計畫只處理「讀者看不看得懂、用不用得到」，不改任何曆法／天文語意。

---

## 0. 兩個前提

1. **首頁保持極簡。** 不把長段說明文字放回首頁。理解靠「動畫＋互動＋可選的說明入口」，不是靠常駐文字。
2. **讀者沒有太多先備概念。** 預設讀者是「聽過八字、但不熟干支規則，也不懂天文」的人。凡是需要 TT、UT1、LCM、黃經、離散候選等概念的地方，都要先給白話，術語放在後面或收進說明裡。

由此推出的判斷規則：

- 首頁常駐元素只允許：圓盤、選定時間、極少數控制項。其他一律收進「怎麼讀」或「工具」。
- 首頁任何說明必須能在 **3 秒內看完**，或由使用者主動打開。
- Research 可以長，但每一節第一句必須是白話結論。

## 2. 階段與任務

每個任務一個 PR。勾選代表已合併。

### 階段 A — 快修（約 1–2 天）

讓既有功能「摸得到」、讓既有內容「不矛盾」。

- [ ] **A1 恢復尺度切換與播放（極簡形式）。**
  預設狀態只多一個小的播放鍵（放在選定時間讀數旁）；尺度切換放在「工具」打開後的第一排。移除 `navigation-workspace.css:77/87` 的強制隱藏。
  驗收：桌機與手機都能在兩次點擊內切換尺度、開始／停止播放。
- [ ] **A2 新增「可達性」測試。**
  README 列出的每個使用者功能（尺度、播放、分類、找時間、太陽時、回到現在）都要有可見且可點的入口；入口消失時測試必須失敗。
- [ ] **A3 修 Research 03 的矛盾。**
  摺疊列標明它看的是哪個時間點，例如「目前時間（Δ = 0）：日柱與時柱皆已解析」，或改為顯示 +24,000 年的狀態。
- [ ] **A4 修 Research 03 的層級倒置。**
  答案（干支＋可判／未定）成為最大字；「年柱／月柱」降為標籤。
- [ ] **A5 介面文字全面在地化。**
  所有可見英文 eyebrow 與標籤改為中文（品牌名「BaZi Time Atlas」可保留）。

### 階段 B — 首頁：極簡但讀得懂（約 1 週）

原則：**不加常駐文字，用動畫與互動說明。**

- [ ] **B1 開場快轉動畫。**
  第一次載入時用 3–4 秒從 −48 小時快轉到現在：內環轉很多、外環幾乎不動，直接展示「每一層跑得不一樣」。重用既有 playback（`src/interaction/kinetic-playback.js`），不新增依賴。
  `prefers-reduced-motion` 時直接顯示最終狀態。點擊或拖曳可立即跳過。
- [ ] **B2 一次性的操作提示。**
  第一次造訪時，在圓盤上淡入一行「拖曳任一圈，移動時間」，第一次拖曳後消失，之後不再出現（記在 localStorage，讀寫包 try/catch）。
- [ ] **B3 「怎麼讀」入口。**
  右上角一個小的「?」或「怎麼讀」。打開後是疊在圓盤上的標註層：
  - 五圈名稱（時／日／太陽／月／年）；
  - 「越內圈越快、越外圈越慢」；
  - 金線＝你選的那一刻；
  - **週期長度尺**：每圈轉一整圈要多久（時 5 天、日 60 天、太陽 1 年、月 5 年、年 60 年），以對數軸呈現。
  關閉後首頁恢復極簡。
- [ ] **B4 讀數可讀性。**
  - 金線在正在讀的干支處留缺口（或標籤移到線的一側），不再穿字；
  - 正在讀的干支：桌機至少 14px、手機至少 13px；
  - 非選定標籤在手機上減量（只標選定 ±2 格），不再全部等比例縮小；
  - 修正換柱邊界處的標籤重疊。
- [ ] **B5 停在「現在」時讓時間走動。**
  讀數秒數每秒更新；切出分頁時暫停。
- [ ] **B6 點擊目標與導覽字級。**
  所有可點元素至少 44×44px（視覺可以小，點擊區要夠）；導覽與工具文字至少 12px。
- [ ] **B7（需原型比較）每環低彩度識別色。**
  目前「分類」模式比預設好讀，因為有顏色區分。做 2–3 個方案放 `prototypes/`，在 1440 與 390 比較後再決定是否進 production。

### 階段 C — 設計基礎（約 1 週）

- [ ] **C1 字級階梯。** 落實 constitution 的 7 級字級為 token；有意義的文字不得小於 12px（圖表註記最小 11px）。
- [ ] **C2 色彩 token 統一。** Atlas、Research、Birth 共用一份 `tokens.css`；頁面只引用 token，不直接寫色碼。
- [ ] **C3 字型。** 自託管 Noto Sans TC 子集；數字使用 `font-variant-numeric: tabular-nums`。
- [ ] **C4 CSS 層級。** 導入 `@layer`（tokens → base → components → page → overrides），逐步移除 `!important`。
- [ ] **C5 stylelint。** 限制 font-size 與顏色只能取自 token，新 PR 不得新增 `!important`。

### 階段 D — Research：給沒有概念的讀者（約 1–2 週）

- [ ] **D1 每節第一句白話結論。** 例：
  - 01：「年和日的干支大約 1,980 年會一起回來，但季節位置要到 24,000 年才也對上。」
  - 02：「就算到了 24,000 年，十二個節氣的時間都還是提早了 10 到 14 天。」
  - 03：「所以 24,000 年後，年柱和月柱可以一樣，但日柱和時柱沒辦法確定。」
- [ ] **D2 把開頭的儀表板移到後面。** 第 01 節之前只留標題、一句話問題和三節目錄；統計卡與 8 格狀態卡移到各節內或收進摺疊。
- [ ] **D3 術語白話化與術語表。** 第一次出現時就地解釋，並建一份頁尾術語表（草稿見第 4 節）。TT、UT1、LCM 等只出現在「深入」摺疊裡。
- [ ] **D4 標題階層。** H2 > H3 > 內文，修正 H3 比 H2 大、H2 只有 13px 的問題。
- [ ] **D5 新增或替換圖：**
  - 01 **三軌對齊圖**（constitution 方案 B）取代目前的數字卡片；
  - 02 **偏移累積折線圖**（橫軸 0→24,000 年、縱軸提早天數），放在棒棒糖圖之前；棒棒糖圖改為從 9 天起算的點圖；
  - 03 **證明鏈分岔流程圖**（✓／?／✗ 節點），說明為什麼日柱與時柱無法判定。
- [ ] **D6 減少控制項。** 目前約 15 個摺疊、39 個可見控制項；主線閱讀路徑上只保留每節一個互動。
- [ ] **D7 可用性測試。** 找 5 位沒有天文背景的人，給三個任務並記錄回答時間與卡住的地方：
  1. 這個網站在講什麼？
  2. 找出某個日期的月柱。
  3. 為什麼 24,000 年不算完整週期？

## 3. 流程調整

1. **先量讀者，再量像素。** 在階段 B、D 完成之前，暫停材質／shader 的微調（H2.x 系列）。
2. **每個視覺 PR 要回答一個讀者問題**，例如「第一次來的人看得出金線是什麼嗎？」，而不只是視覺問題。
3. **原型與 production 對照。** 從 `prototypes/` 移植的 PR，附同一狀態、同一尺寸的原型截圖和 production 截圖。
4. **可達性測試是硬門檻**（A2）：功能入口不見時 CI 失敗。
5. **每 10 個左右的 PR 做一次整頁檢查**，避免只做局部最佳化、一層層疊覆蓋。
6. **動畫規則：** 只動 `transform`／`opacity`；全部支援 `prefers-reduced-motion`；在中階 Android 手機上確認不閃爍（參考 `docs/4k-*.md` 的事故紀錄）。

## 4. 術語白話對照（草稿，D3 使用）

| 術語 | 白話說法 |
| --- | --- |
| 干支／六十甲子 | 10 個天干和 12 個地支輪流配對，60 組一輪 |
| 四柱 | 用年、月、日、時各一組干支來描述一個時間點 |
| 節（十二節） | 一年中 12 個換月的時間點，例如立春、驚蟄；八字的月份從這裡開始換 |
| 立春 | 八字裡「換年」的時間點，同時也是換月 |
| 太陽黃經 | 太陽在一年循環中走到的位置，用 0–360° 表示 |
| 離散候選 | 只看曆法數字時「看起來會重複」的年數，還沒用真實天文驗證 |
| 公曆代理 | 用公曆日期來近似季節位置；方便計算，但不是真正的節氣時刻 |
| 相位 | 在一個循環裡走到哪裡（例如 60 組裡的第幾組） |
| TT／UT1 | 兩種天文時間標準；處理數千年尺度時，兩者差距會影響日和時的判定 |
