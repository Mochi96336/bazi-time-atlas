# Research 01 / R22 — 原生三層半圓：相位、速度與公倍數教學提案

> **狀態：設計規格 Draft，尚未實作 UI。**
> 基準為 repository `main` 的原生 R16 phase fan；不承接 R19–R21 事件列／弧線／區間帶。
> 目的不是再換圖皮，而是讓觀眾透過主頁一致的三層半圓，看懂「各層差多少 → 哪兩項先對齊 → 公倍數為何是 24,000」。

## 0. 決議

保留原生三層同心半圓、左至右的最短有號偏移尺度，以及垂直共同零點。以 **真實模型的相位取樣** 控制標記，以 **經設計但不偽造物理時間的教學播放流程** 引導使用者辨認公倍數。保留原本所有選取時間入口、干支四柱時間狀態、日序計算、02/03 天文驗證邊界。

**不做：**
- 不用 R19／R20／R21 靜態事件軌道取代主圖，也不改成三條直線。
- 不將每層動畫任意調成相近角速度；不把「最短有號相位」當成真正累積旋轉。
- 不新增第二個 Δ owner、複製時間控制器，或把某個已閉合的週期冒充八字完整重遇。
- 不改 `recurrenceState()` 的曆法算法作為設計捷徑；不直接改正式預設。

## 1. 當前原版證據與缺點

閱讀的 repository main 來源：

- `src/recurrence-view.js`：`FAN_START=-170`、`FAN_END=-10`、`CURSOR_ANGLE=-90`。徑向順序 `day [270,360]`、`year [360,450]`、`gregorian [450,560]`；三層已有共用零點，並以 `signedShortestPhase` 算標記位置。
- `src/recurrence/phase-fan-geometry.js`：`signedShortestPhase()` 回傳 `[-m/2,+m/2]` 的最短位移，半週期端點有符號重標定（相位連續但「最短距離」座標不連續）。
- `src/recurrence/gregorian-cycle.js`：年序 `Δ mod 60`、公曆 `Δ mod 400`、日序為同月同日的真實 Gregorian ordinal 差 `mod 60`。遇到無效日期（如 2/29 的對應平年）日序為 `null`，不是 0。
- `src/recurrence/delta-playback-controller.js`：既有播放依整數年更新，`yearsPerSecond=20`；完整 24,000 年需 1,200 秒（20 分鐘），也可能在較高速度的未來模式略過重要命中年份。
- `recurrence.html`：現存 `#recurrence-wheel`、`#delta-slider`、`#research-delta-play`、研究時間／四柱與 02/03 章節。R22 必須沿用。
- `recurrence.css`／`research-color-calibration.css`：既有 Graphite／Brass／冷灰藍材質語彙；不得用大量彩色卡片、強膠囊或 dashboard 重新詮釋。

當前最主要的 UX 問題不是半圓造型，而是：使用者在一般播放時未必能捕捉「兩項同時歸零，第三項還差多少」；也未必明白日序為何看似跳動、外層很慢而中層較快。

## 2. 數學契約：唯一時間模型

固定基準日期 `B=(year, month, day)`，選取非負整數年 `Δ`，與正式模型相同：

```text
G_residue = Δ mod 400                      公曆結構，單位：年
Y_residue = Δ mod 60                       名義年序，單位：年
D_elapsed = ordinal(B.year + Δ, B.month, B.day) − ordinal(B)
D_residue = D_elapsed mod 60               日序，單位：日

signed = signedShortestPhase(residue, modulus)
closed = (residue == 0)                    三層分別判斷
```

不能把 `G`、`Y`、`D` 原始差值直接以相同單位比較；三層共用「零點方向」，但每圈的量綱不同。命中的必要條件是各自精確餘數為 0。Δ=0 是恆等參照，必須與非零重遇區分。

**完整圈數**與**半圓位置**是兩個不同變數：

| 層 | 理論累積圈數 | 一年實際增加 | 半圓標記代表 |
|---|---|---|---|
| 公曆結構 | `Δ / 400` | 1/400 圈／年 | `signed(Δ mod 400,400)` |
| 名義年序 | `Δ / 60` | 1/60 圈／年 | `signed(Δ mod 60,60)` |
| 日序 | `D_elapsed / 60` | 同月同日一年約 365 或 366 日 ≈ 6.09 圈／年 | `signed(D_elapsed mod 60,60)` |

日序真實累積圈數從 GregorianOrdinal 計算；「6.09」只能放在說明文字作平均直覺，不得拿它覆蓋真實閏年與平年算法。

**最關鍵的誤讀防線**：160° 半圓是「從共同零點量有號最短距離」的折疊刻度，**不是一圈實際旋轉 360° 的時鐘**。穿越半週期符號翻轉時，在另一側重定位，不能以 CSS 連續補間描述為相反方向旋轉。

## 3. 公倍數推導必須從圖形中看得出來

固定範例基準日期：2026-09-13。

| Δ | 公曆最短差（年） | 年序最短差（年） | 日序最短差（日） | 主敘述 |
|---:|---:|---:|---:|---|
| 0 | 0 | 0 | 0 | 基準狀態，非非零重遇 |
| 400 | 0 | −20 | −3 | 只有公曆閉合 |
| 1,200 | 0 | 0 | −9 | `LCM(400,60)=1,200`；日序還差 9 日 |
| 1,980 | −20 | 0 | 0 | 基準相關的年＋日局部重遇，但公曆未閉合 |
| 8,000 | 0 | +20 | 0 | 公曆＋日序閉合；年序尚差 20 年 |
| 24,000 | 0 | 0 | 0 | 三項首次同時非零閉合，**離散候選** |

演算解釋順序不可被畫面打亂：

1. 公曆結構 400 年與名義年序 60 年 → `LCM(400,60)=1,200`。
2. 400 個公曆年固定經過 146,097 天，`146,097 mod 60 = 57 (= −3)`；因此每 400 年日序仍差 3 日，需 20 個 400 年區塊 → `8,000` 年讓公曆＋日序同時閉合。
3. `LCM(1,200,8,000)=24,000` 年，三層同時非零閉合。
4. `1,980` 是特定基準日期的年序＋日序相遇，**不**要寫成所有日期共有的簡單固定 LCM；其他日期可先在 `6,180` 或 `16,080` 年相遇。
5. R22 結果不能直接宣稱「四柱完全重複」：真正立春／節界與年柱判定屬後續 02／03 的驗真。

**驗收最小口述測試**：看完圖不翻文字，觀察者能說明「+1,200 哪兩項先對齊、還缺哪一項」、「+8,000 改成哪兩項對齊」、「最後為何要找 1,200 與 8,000 的共同倍數」。

## 4. 視覺結構：保留原版半圓

### 4.1 共用幾何與材質

- 單一同心半圓，保持 `[-170°, -10°]` 展開與 `-90°` 零點。外公曆、中年、內日的半徑階層保留為基礎；**在新實驗通過視覺審查前，不動半徑與扁平投影**。
- 所有標記、刻度、零點、軌道必須使用同一變換矩陣；避免投影後中心與讀頭錯位。
- 主頁同源的冷石墨層次＋克制的金屬零點，將「當下指示」「閉合」與「背景刻度」視覺權重分離；明確辨識三層，避免三處大面積強調色。
- **位置第一，顏色第二**：以刻度、零點節點、文字數值、線粗區分結果，色盲或灰階檢視不失去判讀。
- 不用大型卡片把每個餘數重印一遍。動態數值緊鄰各層軌道的視覺焦點；讀者不必上下反覆對照。
- 同一畫布最多一個主要判讀句。例如「公曆與年序已對齊，日序還差 −9 日」。

### 4.2 兩種圖內狀態（不切換成另一種圖）

**Normal**：三個移動標記、共同零點與各自最短有號差，非零閉合只用原本的細節點強調，不播放全屏動畫。

**Milestone hold**：到重點年份時，兩個／三個對齊的圈出現一次低強度的收束回饋（最多短暫 200–300 ms），未對齊那層保留可見差距；數值與敘述清楚標示缺什麼。**不給 Δ=0 一樣的「成功重遇」動態特效**。

## 5. 時間與播放：一條真實 Δ，兩種閱讀節奏

### 5.1 手動閱讀（預設）

- 原本 `#delta-slider`、輸入 Δ、快捷年份與外部事件都走現有 `setDelta`；保留唯一 URL／時間 owner 與既有 01/02/03 共用日期。
- 每個狀態都呼叫現有 `recurrenceState(B, integer Δ)`，日序用真實日數。使用者拖曳時即刻更新，並中止自動導覽。
- 兩次離散年份之間**不計算**假的小數年、假日數或假年柱。半圓每一幀只描畫已取樣的真實狀態。

### 5.2 自動導覽（教學節奏，不宣稱等速歷史）

一般的 `20 years/s` 播完 24k 要 20 分鐘；建議另設 Guided playback 層，但**不是另一套時間模型**。

- 依當前基準動態推導排序過的停止點：`[0,400,1200,firstYearDay,8000,24000]` 去重、合法性檢查後排序；`firstYearDay` 不一定落在 +8,000 之前。
- 每段距離太遠時，允許明確標示「略過 Δ N 年」並**跳轉**到停靠點前的窗口；不把這段跳躍渲染成物理連續旋轉。窗口內逐年走訪，例如前 `±20` 或 `±40` 年，讓使用者看見閉合的相位靠近與離開。
- 命中年份**強制取樣該精確整數**，即使 frame 掉幀也不能略過；停留建議 1.4–2.2 秒（待手機使用測試調整），顯示「已對齊兩項／第三項尚差 X」。
- 暫停、重播、改基準、手動拖曳、切換分頁、減少動態偏好都有清晰取消／恢復語意；按「暫停」不能被排程的舊 callback 自動重新啟動。
- 動畫進度顯示的是「教學段落 N／M」，不是把段落所需秒數等同歷史經過年數。UI 可保持原本一個「播放」入口；不要兩個並列時間滑桿。

### 5.3 高速日序的真實性

- 在整數年的 long-range 讀法中，日序每跨一個同月同日年份，真實日數前進 365／366 日。若只看餘數，**折回後位置**通常等價於 +5／+6 日；但實際完整前進約六圈。圖上不可假裝只前進了 5／6 日。
- 明確區分 `unwrappedTurns = D_elapsed / 60` 與 `signedResidual`；完整圈數只在一個輕量說明或展開的檢視器顯示，不在日序圖上塞大量四五位數字。
- 不提供「把日序做成小幅慢速連續轉動」的偽動畫。若需要真正看 60 日序如何循環，後續分支可做 **實際逐日局部慢放**，但必須先設計與現有整數年 Δ 的資料契約（例如僅視覺局部 microscope、不得回寫虛構 fractional Δ），且不阻擋 R22 第一版。
- `signedShortestPhase` 在 ±半週期重新標定時禁止簡單 CSS transform tween 橫越整個半圓；可用瞬時重定位與簡短的方向提示，避免視覺上倒轉。

## 6. 版面：一張主圖，不是儀表板

桌面（≥ 1024px）：左側寬幅半圓佔主要視覺，右側只有當下結果句與支持數值；操作區附著同一 Δ，公式證明放主圖下方有節奏地分段閱讀。研究時間與四柱維持在入口附近，隨同一選取日期更新。

手機（320／390px）：先讓研究問題與基準／比較干支容易辨認，接著**讓半圓完整、足夠大**，不讓同一標籤重複三次。圖下緊接目前缺少的相位及單一 Δ 播放／拖曳；進階年數輸入、計算細節與補充週期表可以折疊，但**主圖不折**。避免膠囊按鈕群與橫向 overflow。

現有年度時間條保留；01 解釋了離散零點後再展開 02 節氣驗證與 03 四柱後果。負空間分層，不採多框 dashboard。

## 8. 實作順序（各階段獨立審查，不早合併）

**P0 — 冻結行為 / 基線證據**：擷取當前 main 之 320／390／768／1440 截圖、Δ=0／400／1200／1980／8000／24000 與特殊基準；核對原版半圓材質、幾何、焦點與 mobile 裁切，定出不能退步的視覺基線。

**P1 — 數學 view-model 與採樣測試**：不動正式 UI。以 pure function 算三個真實 signed offsets、閉合狀態、完整圈數、候選 checkpoint；完成 leap day、不同 base、24,000、±half-period 跳側單元測試。

**P2 — 半圓內資訊設計**：只在 opt-in 實驗入口上調標記／零點／文字位置、層級、狀態句、閉合回饋。通過手機不裁切／不遮蔽，不另造時間控制。

**P3 — 停靠式導覽播放**：沿用現有時間狀態，新增 guided adapter，顯式區分「跳年」「逐年取樣」「精確停靠」「使用者取消」。用 mock requestAnimationFrame 測 frame 掉幀仍會落在 checkpoint，避免重複 callback。

**P4 — 守門式驗收**：主頁圖形語言對照、手機實機截圖、鍵盤/讀屏/減少動態、R16 預設對照、02/03 同步、研究數字回歸；用不了解模型的讀者核對 1,200→8,000→24,000 是否能理解，再決定是否推廣。

## 9. 完成定義與停止條件

**必須通過：**
1. 任意 B、Δ 看到的三層原始餘數、signed shortest 值與閉合判定均等於正式模型；無效日序不可顯示零點已閉合。
2. 2026 範例 400／1,200／1,980／8,000／24,000 的結果逐一精確吻合；1900／2100 的局部重遇年份會改變而不是硬編碼。
3. 不論 fps 和導覽速度，指定 milestone 不被越過；手動拖曳或隱藏頁面後沒有殘留播放計時器。
4. 「半圓位置＝最短差，並非實際圈數」可從圖說辨認；在 ±half-period 跳側時沒有假的逆行過場。
5. 原本四柱當刻干支、單一 Δ、時間選擇、02/03 的節氣真實性與主頁材質不退化。
6. 320／390／768／1440px 無裁切、數字相撞、圖例重複；低動態模式可完整操作。
7. GitHub quality、visual 和 cross-page regression 全部通過後才考慮合併；單純 CI 全綠也不等於視覺過關。

**停損條件：** 如果動畫只靠大量說明文字才能懂公倍數、如果日序在長年快轉下造成虛假連續旋轉印象、或如果手機為了容納圖例而縮到難以閱讀，先退回原生半圓再設計，不用新介面強行取代。

## 10. 第一個提案畫面應該回答的三句話

- `+1,200 年：公曆、年序都回到 0；日序還差 −9 日。`
- `+8,000 年：公曆、日序都回到 0；年序還差 +20 年。`
- `+24,000 年：三個零點同時成立，這是離散候選，尚需節氣驗真。`

三句話都必須能**從原生半圓的三個位置直接讀出來**，而不是依賴另一張靜態時間軸。
